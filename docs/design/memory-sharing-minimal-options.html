Design scope and implementation notes

These are five visual treatments at the exact same location, not five different navigation systems. Options 1, 2, 3 and 5 use a switch. Option 4 uses a native macOS checkbox as the Toggle presentation.

Option 1 makes the action explicit. Option 2 uses the least space but relies on help text to explain what the switch shares. Option 3 adds a static sharing symbol as a cue. Option 4 follows the standard macOS checkbox pattern. Option 5 groups the controls visually with a quiet outline.

In the app, use the system Toggle, a gear symbol button with the accessible name “Memory settings,” and separate hit targets for the disclosure and accessories. Preserve keyboard focus when state refreshes. The gear can open a compact settings menu or popover; it should not reopen the current full memory/status sheet.

The selected implementation uses a native SwiftUI switch, SF Symbols gear button, semantic system styling and a transient settings popover. It follows Apple’s toggle guidance and popover guidance. Supported agents render from a profile collection; the existing Claude Code and Codex adapters and wire contract are unchanged. Additional adapters still need implementation.

The browser samples approximate native controls. They make no calls to agents, do not modify any project setting or memory, and are separate from the native Swift implementation of option 5. The experimental flag-off preview hides the sharing accessories while retaining the memory browser.

The small memory list and reader here are placeholders for the existing browser, not a proposal for a new external notes store. Advanced details retain the existing trial’s Twine memory location; new libraries use the Handshake location.

This selected design supersedes the earlier sidebar, toolbar and inspector placement alternatives. Both sharing controls stay in the requested header location.
