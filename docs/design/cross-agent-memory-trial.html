Native API integration

The installed Codex 0.164 build requires external_agent_memory_import. Twine starts only its importer child as codex --enable external_agent_memory_import app-server. Saved configuration is unchanged; both memory stores remain native.

The core inspects effective Codex configuration and calls externalAgentConfig/detect. On the explicit Import action it submits the selected project’s MEMORY item to externalAgentConfig/import. It matches completion to the import ID and selected source; an accepted request alone is unconfirmed.

The installed Codex build supplies the memory migration schema. Twine reports incompatible or unavailable native APIs instead of creating another memory store. Detection and import transport are described in the official Codex app-server documentation.

Keep historical results separate

The earlier 1,000-note publication measurements and catalog-based model tests belong to the retired external design. Legacy sharing is disabled. Old bodies remain in the former app state for historical comparison. The new native app state has no serving library, and legacy bodies are not used for native delivery.

Native import copies a snapshot. Later changes need another native import; deleting a source does not revoke imported copies or existing conversation context. The trial makes no AMIS conformance or automatic reverse-sync claim.
