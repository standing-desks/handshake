01 / DISCOVER

A small starting context

Supported launches receive native discovery instructions, up to eight short topic previews, and access to the shared catalog. Agents select relevant full records.

02 / RETAIN

New notes enter automatically

With the local policy enabled, Twine refreshes every five seconds while the folder is open. New valid inbox files become accepted snapshots.

03 / CORRECT

Inspect and withdraw

Changed source files are held. Withdrawal removes future delivery and suppresses identical content. Accepted history remains available for inspection.

Try a handoff you can verify

  1. Add this note in Twine:
    # Trial convention
The example release checklist is called the cedar checklist.
  2. Ask a newly launched Codex agent: “Read the shared folder memory. What is the example release checklist called? Cite the record you read.”
  3. Ask Codex: “Retain this harmless trial fact in the shared folder inbox: the cedar checklist starts with the focused test suite.”
  4. Wait for the next refresh and inspect the accepted note in Twine.
  5. Launch Claude Code in the same folder and ask: “Read the shared folder memory and tell me what the cedar checklist starts with. Cite the record you read.”
  6. Repeat in the opposite direction. Withdraw the trial notes when finished.

Check the actual tool reads. A published file or injected catalog proves delivery plumbing; it does not prove that a model retrieved, understood, or followed the memory.

What this build implements

AreaTrial behaviorBoundary
ScopeCanonical folder binding; locally enabled policy.Different worktrees and renamed folders have separate bindings.
Native integrationCodex developer instructions and Claude appended system prompt, including workflow and resume launches.No personal/global native-store synchronization.
RetentionSQLite ledger, exact snapshots, source labels, content hashes and withdrawal suppression.128 retained notes, 16 KiB per note. Exact-byte suppression does not catch paraphrases.
RecoveryPolicy and records commit before catalog publication; failed views can be rebuilt.Enabled launches fail closed if the shared view cannot be published.
InteroperabilityTwo harnesses use the same local file-based library.No AMIS wire conformance, semantic consolidation or OMPI adapter yet.

Disabling stops new intake and delivery. Withdrawal is not erasure and cannot revoke already-loaded model context. Notes stay on this Mac until a harness reads them; selected content may then be sent to that harness’s model provider.
