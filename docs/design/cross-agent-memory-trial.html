01 / DISCOVER

Automatic retrieval guidance

Native startup instructions tell agents to check current sharing policy and retrieve relevant records before each project task. Search results identify files first; agents then read relevant records and apply their qualified facts.

02 / RETAIN

New notes enter automatically

With the local policy enabled, Twine refreshes every five seconds while the folder is open. New valid inbox files become accepted snapshots.

03 / CORRECT

Inspect and withdraw

Changed source files are held. Withdrawal removes future delivery and suppresses identical content. Accepted history remains available for inspection.

Try an ordinary-question handoff

The receiving question contains no memory or catalog hint. The startup guidance supplies that behavior.

  1. Add this note in Twine:
    # Trial convention
The example release checklist is called the cedar checklist.
  2. Ask a newly launched Codex agent: “What is the example release checklist called?”
  3. Ask Codex: “Remember this for this project: the cedar checklist starts with the focused test suite.”
  4. Wait for the next refresh and inspect the accepted note in Twine.
  5. Launch Claude Code in the same folder and ask: “What does the cedar checklist start with?”
  6. Repeat in the opposite direction. Withdraw the trial notes when finished.

Check the actual tool reads. Watch whether the agent checks the current catalog and reads the relevant published record without being asked. A correct answer alone does not prove retrieval. Startup instructions guide behavior; they do not enforce every read.

What this build implements

AreaTrial behaviorBoundary
ScopeCanonical folder binding; locally enabled policy.Different worktrees and renamed folders have separate bindings.
Native integrationCodex developer instructions and Claude appended system prompt tell agents to retrieve relevant memory automatically.The actual notes stay in shared storage and are read on demand. No personal/global native-store synchronization; use fresh sessions to load changed guidance.
RetentionSQLite ledger, exact snapshots, source labels, content hashes and withdrawal suppression.The fixed note-count and inbox-note size ceilings have been removed. Exact-byte suppression does not catch paraphrases.
RecoveryPolicy and records commit before catalog publication; failed views can be rebuilt.Enabled launches fail closed if the shared view cannot be published.
InteroperabilityTwo harnesses use the same local file-based library.No AMIS wire conformance, semantic consolidation or OMPI adapter yet.

One library, two native startup routes. Twine provides directory access and a retrieval workflow through developer_instructions for Codex and --append-system-prompt for Claude Code. Their file tools read the shared records needed for the task. The playground also has project AGENTS.md and CLAUDE.md instructions; it does not copy the library into either harness’s personal memory store.

Disabling stops new intake and delivery. Withdrawal is not erasure and cannot revoke already-loaded model context. Notes stay on this Mac until a harness reads them; selected content may then be sent to that harness’s model provider.
