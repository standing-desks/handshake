A standard home for Twine memories

The canonical AMIS record stays in Twine. Each agent receives a native representation containing the memory itself.

~/Library/Application Support/Twine/memories/
projects/<project UUID>/
├── library.amis.json   Full records and history
├── bindings/          Local ownership and recovery
├── journal/           Publication plans and policy
├── blobs/             Exact native before/after bytes
├── receipts/          Verified native file writes
└── native/codex/      Project-native CODEX_HOME

Claude’s native destination

~/.claude/projects/twine-<project UUID>/memory/

Twine selects the documented autoMemoryDirectory setting for that invocation, while preserving the agent’s configuration, authentication and Twine’s observer hooks.

<project-native CODEX_HOME>/memories/extensions/ad_hoc/notes/

How updates, conflicts and overlap are handled
  • Revision: a uniquely attributable native edit returns to its original source identity and appends an immutable revision. Twine updates the derived view and publishes the current native representation.
  • Feedback: owned exports are recognized. A generated Codex registry snapshot keeps known delivered ancestry and is exported to Claude without being fed back into Codex’s own input notes.
  • Conflict: ambiguous or concurrent edits are preserved and held. Timestamps and directory order do not choose a winner.
  • Overlap: exact duplicate text can share a view. Semantically overlapping summaries can remain separate; the trial’s two seeded facts currently have an additional native-summary view.
  • Removal: missing source files do not silently erase history. Explicit withdrawals append revisions and native corrections. A generated native summary can retain an old claim until its harness refreshes it.
What the UX tests caught and changed
  • Expected native-session deferral was shown as a red sync failure. It now returns the persisted waiting snapshot.
  • The standard disclosure control did not open reliably in the scaled sheet. A simple accessible button now expands the same native path details.
  • The expanded tests wait for native publication itself, rather than treating an earlier AMIS write or an unchanged status label as delivery proof.
  • The live test now checks the selected harness in persisted workflow state before asking. A global submenu selector previously launched Codex for the case labeled Claude; that result was discarded and the real Claude case was rerun.
